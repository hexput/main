- (decision) Paradigm confirmed with user: Hexagonal / Ports & Adapters at the transport boundary (UDS, Named Pipe, TCP+TLS, WebSocket as adapters into one internal RPC/message port, per PRD FR-9's identical-behavior-across-transports requirement) combined with an Actor model for the runtime core (Backend connections and Plugins as actors with owned state and mailboxes) -- fits the stateful, event-driven Plugin model (FR-17..FR-23) and the non-blocking requirement (FR-16) better than a plain layered/service architecture would.
- (decision) Session state (Plugin registrations, Global Variables, per-backend Config from FR-1/FR-3) is owned by a Session object that outlives the transient connection actor -- confirmed by user. A Session has a lifetime/TTL: after a disconnect with no reconnect within that TTL, the Session (and its Plugins/state) is torn down. This refines PRD FR-21's 'disconnect-without-reconnect' teardown trigger from immediate to TTL-based.

This is DIFFERENT in scope from the PRD's per-backend Config (Glossary: 'Per-connection settings... Not a static file', FR-1: 'no file-based configuration path... for per-backend settings') -- that decision stands unchanged. - (decision) Confirmed: Global Variables are NOT actor-mailbox-owned state -- they live in a separate shared concurrent store (DashMap-like), reachable both by ordered/priority handlers (via the Plugin actor's sequential path) and by async=true handlers (spawned outside the actor's ordering, touching the store directly). The Plugin actor itself owns identity/event-routing/priority-ordering, not the Global Variable values.
- (decision) New requirement surfaced: Global Variables need a configurable BEHAVIOR/lifetime strategy per-variable, separate from the locking strategy (FR-20): 'forever' (default, persists for Session lifetime), 'ttl: <duration>' (value expires/resets after duration since last write), 'separate_each_trigger' (each Event invocation gets an independent, non-shared value despite being declared global), 'based on a key' (variable holds independent values partitioned by a key -- exact key source not yet specified by user, flagging as open question). This is PRD-level scope (FR-25), not just an implementation note -- routing it to the PRD.
- (decision) Confirmed: capability checks (FR-6/7) and Resource Budget enforcement (FR-8) must go through ONE shared enforcement point used by all three execution paths (Direct, Cached, Plugin Event handlers) -- not three independent implementations. This is AD-worthy: prevents the Plugin path silently drifting from the Script path's security/budget guarantees.
